================================================================================
 FlowSim CFD v2.0 — Fix: ModuleNotFoundError: No module named 'uvicorn'
================================================================================

THE ERROR:
  ModuleNotFoundError: No module named 'uvicorn'

WHAT THIS MEANS:
  Python cannot find uvicorn even though it appears to be installed.
  This almost always means one of three things:
    1. The virtual environment (venv) is NOT activated
    2. uvicorn was installed into a DIFFERENT venv or Python
    3. The venv is broken / corrupted

NOTICE IN YOUR PROMPT:
  Your prompt shows: (venv) PS D:\...
  The (venv) prefix suggests the venv IS activated.
  But the error says uvicorn is missing from it.
  This means the venv was probably created but uvicorn was never
  successfully installed into it, OR it was installed into a different venv.

    This forces Python to use the uvicorn from the current venv,
    avoiding any path confusion with system-level executables.


================================================================================
 WHY "python -m uvicorn" IS SAFER THAN JUST "uvicorn"
================================================================================

When you type:
  uvicorn app.main:app ...

Windows looks for uvicorn.exe in your PATH environment variable.
If there is a broken or old uvicorn.exe somewhere on PATH, it may
get picked up instead of the one in your venv.

When you type:
  python -m uvicorn app.main:app ...

Python runs uvicorn as a MODULE from the CURRENTLY ACTIVE Python.
This guarantees it uses the uvicorn installed in your active venv.
No PATH confusion possible.

USE THIS COMMAND FROM NOW ON:
  python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000


================================================================================
 ALTERNATIVE: INSTALL USING python -m pip (not just pip)
================================================================================

Another cause of this error: "pip" on your PATH points to the system Python's
pip, not the venv's pip. So pip install puts packages into the WRONG Python.

To guarantee packages go into the venv, always use:

    python -m pip install uvicorn[standard]

Instead of:

    pip install uvicorn[standard]

These should be equivalent when the venv is active, but python -m pip
is 100% guaranteed to use the correct pip.

Full safe install sequence:

    python -m pip install --upgrade pip
    python -m pip install "numpy>=2.3" --only-binary=:all:
    python -m pip install "scipy>=1.16" --only-binary=:all:
    python -m pip install "pydantic>=2.10" --only-binary=:all:
    python -m pip install "pydantic-settings>=2.6" --only-binary=:all:
    python -m pip install "uvicorn[standard]"
    python -m pip install fastapi sqlalchemy aiosqlite python-multipart httpx pytest pytest-asyncio
