1. PROJECT OVERVIEW
═══════════════════════════════════════════════════════════════════════

Apex Forex Broker is a self-hosted desktop forex trading simulation
platform written in C++ and Python. It combines a high-performance
C++ indicator engine with a full Python trading application featuring:

  - Live price feeds (WebSocket: TwelveData, Polygon, OANDA, or demo)
  - 22-indicator signal fusion engine with ML filter
  - Full manual trading: market orders, limit orders, stop orders
  - Automatic SL/TP execution, trailing stops, margin call protection
  - Kelly-criterion position sizing with VaR/CVaR risk metrics
  - SQLite-backed persistence (positions, history, signals, equity curve)
  - Professional Tkinter GUI with candlestick charts and analytics
  - C++ shared library for O3-optimised indicator math via ctypes

Language split:
  C++    — math_engine.dll/.so  (indicators, financial math, statistics)
  Python — everything else      (trading logic, GUI, database, feed)

Platform: Windows 10/11 (primary), macOS 11+, Ubuntu 20.04+
Python  : 3.10, 3.11, or 3.12
C++     : C++17 (MSVC 2019+, GCC 10+, Clang 12+)

4. C++ MATH ENGINE
═══════════════════════════════════════════════════════════════════════

Files:
  cpp/include/math_engine.h     — Public C API (pure C extern "C")
  cpp/src/math_engine.cpp       — Implementation (~450 lines)
  cpp/bridge.py                 — Python ctypes wrapper

Why C++?
  Indicator calculations run on every completed price bar for every
  pair and timeframe. With 12 pairs × 6 timeframes × 22 strategies,
  this happens hundreds of times per second. C++ with -O3 optimisation
  is 5–20× faster than equivalent NumPy code for these inner loops.

Exported functions (all use raw double* arrays):

  Moving Averages:
    apex_ema(src, dst, n, period)          Exponential Moving Average
    apex_sma(src, dst, n, period)          Simple Moving Average
    apex_wma(src, dst, n, period)          Weighted Moving Average
    apex_hma(src, dst, n, period)          Hull Moving Average
    apex_wilder(src, dst, n, period)       Wilder Smoothing

  Oscillators:
    apex_rsi(close, dst, n, period)        RSI (Wilder smoothing)
    apex_macd(close, macd, sig, hist, ...) MACD + signal + histogram
    apex_stochastic(h,l,c, k,d, ...)       Stochastic %K and %D

  Volatility:
    apex_atr(h, l, c, dst, n, period)     Average True Range
    apex_bollinger(c, upper, mid, lower, ..)  Bollinger Bands
    apex_supertrend(h,l,c, st, dir, ...)   SuperTrend indicator

  Trend:
    apex_adx(h,l,c, adx, pdi, mdi, ...)   ADX + DI lines
    apex_ichimoku(h,l,c, tenkan, kijun, ..) Ichimoku Cloud (5 lines)

  Financial Math:
    apex_pnl_buy(open, close, lots, ps, pv)   BUY P&L in USD
    apex_pnl_sell(open, close, lots, ps, pv)  SELL P&L in USD
    apex_margin(lots, price, contract, lev)   Required margin

  Statistics:
    apex_var95(returns, n, balance)        VaR at 95% confidence
    apex_cvar95(returns, n, balance)       CVaR / Expected Shortfall
    apex_max_drawdown(cum_pnl, n)          Peak-to-trough drawdown
    apex_sharpe(returns, n)               Annualised Sharpe ratio
    apex_sortino(returns, n)              Annualised Sortino ratio

NaN handling: All output arrays are pre-filled with NaN. Output is
only written for indices where sufficient data exists — exactly
matching NumPy indicator behaviour.

Fallback: If math_engine.dll/so is not found at runtime, bridge.py
automatically uses pure NumPy implementations with identical results.

Build commands:
  Windows (MSVC):
    cl /O2 /LD /EHsc /std:c++17 /Icpp\include
       /Fe:python\cpp\math_engine.dll cpp\src\math_engine.cpp

  Windows (MinGW):
    g++ -std=c++17 -O3 -shared -fPIC -Icpp/include
        -o python/cpp/math_engine.dll cpp/src/math_engine.cpp -lm

  Linux:
    g++ -std=c++17 -O3 -shared -fPIC -Icpp/include
        -o python/cpp/math_engine.so cpp/src/math_engine.cpp -lm

  macOS:
    g++ -std=c++17 -O3 -dynamiclib -Icpp/include
        -o python/cpp/math_engine.dylib cpp/src/math_engine.cpp -lm

  Or use the build scripts:
    Windows : double-click scripts\build_cpp.bat
    Linux   : bash scripts/build_cpp.sh

5. PYTHON MODULES
═══════════════════════════════════════════════════════════════════════

main.py
  Entry point. Parses CLI args, checks dependencies, constructs every
  subsystem in dependency order, wires the data pipeline, and launches
  the GUI (or runs headless).
  CLI: --debug  --headless  --reset-db  --config <path>  --version

core/config.py  — class Config
  Loads config.json with deep-merge against defaults. Saves on every
  .set() call. Supports environment variable overrides:
    APEX_API_KEY    → data_source.api_key
    APEX_PROVIDER   → data_source.provider
    APEX_BALANCE    → account.initial_balance
  Properties: .pairs  .provider  .api_key  .primary_tf  .account_cfg
              .trading_cfg  .signal_cfg  .risk_cfg  .ind_cfg  .ml_cfg

core/logger.py  — functions: setup_logging(), get_logger(), set_level()
  Rotating file handler (10 MB × 5 backups). ANSI colour console.
  Optional JSON log format. Silences noisy third-party libraries.

db/database.py  — class Database
  SQLite connection (WAL mode, row_factory=Row, RLock).
  Tables: accounts, positions, orders, trade_history, signals,
          price_cache, daily_stats, equity_curve
  Key methods: get_positions(), insert_position(), close_position(),
               get_history(), get_history_stats(), insert_signal(),
               snapshot_equity(), get_equity_curve()

auth/account.py  — class AccountManager
  Tracks live prices (bid/ask dict). Computes equity/margin/PnL
  on demand from DB positions. Applies daily swap rollover.
  Key constants: PIP_SIZE, PIP_VALUE, SWAP_RATES, CONTRACT=100,000
  Key methods: update_price(), get_price(), pnl(), margin_req(),
               commission(), snapshot(), apply_swaps(), ticket()

data/feed.py  — class PriceFeed
  Routes ticks from the chosen provider to registered callbacks.
  Providers:
    _DemoSimulator   — GBM + OU mean reversion + trend injection
    _TwelveDataStream — WebSocket wss://ws.twelvedata.com/...
    _PolygonStream    — WebSocket wss://socket.polygon.io/forex
    _OandaStream      — REST streaming (HTTPS chunked)
  All providers auto-reconnect with exponential backoff.

data/bars.py  — class BarAggregator, class _TFBuffer, dataclass Bar
  Converts tick stream into OHLCV bars for 6 timeframes simultaneously.
  Bar properties: .body  .range  .bullish  .upper_wick  .lower_wick
  Max 600 bars per (pair, timeframe) combination.

signals/indicators.py  — class Ind (static methods)
  Pure NumPy indicator library used as fallback when C++ is absent.
  Implements all indicators that math_engine.cpp exports, plus:
  CCI, Williams %R, MFI, Donchian, Keltner, VWAP, OBV, Squeeze,
  Pivot Points, Hurst Exponent, Z-Score, RSI Divergence, MACD
  Divergence, Kalman Filter, Parabolic SAR, Candlestick Patterns.

signals/engine.py  — class SignalEngine
  Subscribes to bar completions. For each bar runs all 22 strategies,
  collects weighted votes, checks filters, calculates SL/TP/lot size,
  saves to DB, and emits callbacks.

risk/manager.py  — class RiskManager
  suggest_lot(): fixed-fraction + fractional Kelly lot sizing
  _kelly_from_history(): computes Kelly f* from trade history
  daily_loss_breaker_tripped(): returns True if daily loss > max_pct
  compute_metrics(): 19 performance metrics using C++ stats functions
  risk_summary(): combined account snapshot + metrics dict

trading/engine.py  — class TradingEngine
  open_market(): place BUY/SELL at current ask/bid ± slippage
  place_pending(): BUY_LIMIT / SELL_LIMIT / BUY_STOP / SELL_STOP
  close_position(): close by ticket, record to history, update balance
  modify_sl_tp(): change SL/TP on open position
  on_price_update(): called every tick — checks SL/TP hits + trailing
  _monitor_loop(): background thread (1s) — pending triggers + margin
  Callbacks: on_trade(), on_close(), on_error(), on_alert()

reports/reporter.py  — class Reporter
  export_history(): writes timestamped CSV to exports/ folder
  append_trade(): auto-appends every closed trade to reports/trades.csv

ui/app.py  — class BrokerApp
  Root Tkinter window. Header bar with live account stats. Left
  watchlist. Right candlestick chart. Bottom 8-tab panel bar.
  Tabs: Trading · Positions · Orders · Signals · History · Analytics
        · Risk · Log

ui/chart.py  — class ChartPanel
  matplotlib TkAgg canvas with candlestick rendering, EMA/BB/ST/VWAP
  overlays, volume sub-chart, RSI sub-chart, signal markers (▲/▼).
  Refreshes every 2 seconds (configurable via ui.refresh_ms).

6. DATA FLOW PIPELINE
═══════════════════════════════════════════════════════════════════════

  [Price Provider] ──tick(pair, bid, ask)──► [AccountManager.update_price]
                                          └──► [BarAggregator.on_tick]
                                                      │
                                              bar completed
                                                      │
                                                      ▼
                                           [SignalEngine.on_bar]
                                                      │
                                           Run 22 strategies
                                           (C++ or NumPy math)
                                                      │
                                           Weighted vote fusion
                                                      │
                                           Filters: confidence,
                                           cooldown, spread, session
                                                      │
                                           Signal emitted
                                                      │
                                       ┌───────────── ▼ ─────────────┐
                                       │      [TradingEngine]        │
                                       │   handle_signal (auto)      │
                                       └─────────────────────────────┘

  Every tick also calls:
    TradingEngine.on_price_update(pair, bid, ask)
      → for each open position on this pair:
        → recalculate live P&L
        → check SL hit → close_position("sl")
        → check TP hit → close_position("tp")
        → advance trailing stop if profitable

  Background monitor thread (1 s):
    → trigger pending orders when price reaches entry level
    → cancel expired pending orders
    → check margin level → margin call / stop-out
    → apply overnight swap charges (once per day at midnight UTC)

7. SIGNAL SYSTEM (22 STRATEGIES)
═══════════════════════════════════════════════════════════════════════

Each strategy votes BUY, SELL, or ABSTAIN. Votes are weighted.
The side with the higher total weight wins if it meets min_confluence.

  #   Strategy                 Weight  Votes on
  ─── ──────────────────────── ──────  ──────────────────────────────
   1  EMA Cross (9/21)           2.5   EMA9 crosses above/below EMA21
   2  EMA-200 Trend Filter       2.0   Price above/below EMA200
   3  MACD Histogram Cross       2.0   Histogram crosses zero
   4  RSI Oversold/Overbought    1.5   RSI < 30 or RSI > 70
   5  RSI Divergence             2.0   Price/RSI divergence
   6  Stochastic Cross           1.0   %K/%D cross in OB/OS zone
   7  CCI ±100                   1.0   CCI outside ±100 band
   8  Williams %R                1.0   %R outside ±80/−20
   9  MFI                        1.0   MFI < 20 or > 80
  10  Bollinger Bands %B         1.5   Price at outer band
  11  SuperTrend Flip            2.5   Direction change
  12  Ichimoku Cloud             2.5   Price vs cloud + TK cross
  13  ADX Trend Strength         1.5   ADX > 25 with DI alignment
  14  Squeeze Momentum           1.5   BB inside KC squeeze release
  15  Donchian Breakout          1.5   Price breaks 20-bar high/low
  16  Keltner Channel            1.0   Price outside KC bands
  17  VWAP Position              1.0   Price vs VWAP
  18  OBV vs EMA                 1.0   OBV above/below its EMA
  19  Candlestick Patterns       2.0   10 pattern types
  20  Pivot Point S/R            1.5   Price at pivot level
  21  Hurst + Z-Score Regime     1.0   Hurst > 0.55 = trending
  22  ML Pattern Filter          3.0   Random Forest (200 trees)

  Total max weight: ~36.0
  Signal emitted when: winning_weight / total_weight ≥ min_confidence
  Default min_confluence: 3 votes  (configurable)
  Default min_confidence: 55%      (configurable)
  Cooldown: 300 s between signals per pair (configurable)

Signal strength levels:
  WEAK         52–60%   (1 dot  ●○○○)
  MODERATE     60–70%   (2 dots ●●○○)
  STRONG       70–80%   (3 dots ●●●○)
  VERY STRONG  ≥ 80%    (4 dots ●●●●)

SL/TP calculation:
  SL = entry ± ATR(14) × sl_atr_mult  (default 2.0)
  TP1 = entry ± SL_dist × tp_rr       (default 2:1)
  TP2 = entry ± SL_dist × 3.0
  TP3 = entry ± SL_dist × 4.0

8. RISK MANAGEMENT
═══════════════════════════════════════════════════════════════════════

Position Sizing (Kelly-Adjusted Fixed Fraction):
  risk_usd  = balance × risk_per_trade_pct / 100
  sl_pips   = |entry − stop_loss| / pip_size
  raw_lots  = risk_usd / (sl_pips × pip_value_per_lot)
  kelly_f*  = (b×p − q) / b   where b=avg_win/avg_loss, p=win_rate
  final_lots = raw_lots × (kelly_f* × kelly_fraction)
  Clamped to: [min_lot=0.01, max_lot=100.0], rounded to lot_step=0.01

Protective Mechanisms:
  Daily Loss Breaker   — blocks trading when daily loss > max_daily_loss_pct
  Margin Call Warning  — alert + trade block when margin level < 50%
  Stop-Out             — force-close all positions when margin level < 20%
  Trailing Stop        — SL advances as price moves in profit direction
  Spread Filter        — signals blocked when spread > spread_filter_pips
  Max Open Trades      — hard limit of 20 simultaneous positions

Risk Metrics computed by RiskManager.compute_metrics():
  Total Trades, Win Rate, Profit Factor, Net P&L
  Gross Profit, Gross Loss, Avg Win, Avg Loss
  Expectancy, Sharpe Ratio, Sortino Ratio, Calmar Ratio
  Max Drawdown, Max DD %, VaR 95%, CVaR 95%

9. FINANCIAL MATHEMATICS REFERENCE
═══════════════════════════════════════════════════════════════════════

Account:
  Margin Required = (Lots × ContractSize × Price) / Leverage
  Equity          = Balance + Floating_PnL
  Free Margin     = Equity − Margin_Used
  Margin Level    = (Equity / Margin_Used) × 100%
  PnL BUY         = (Close − Open) / PipSize × PipValue × Lots
  PnL SELL        = (Open − Close) / PipSize × PipValue × Lots
  Daily Swap      = Lots × SwapRate_pips/night × PipValue
  Commission      = Lots × CommissionPerLot  (default $7/lot)

Statistics:
  Sharpe  = (μ_r − r_f) / σ_r × √252
  Sortino = (μ_r − r_f) / σ_down × √252   (downside std only)
  Calmar  = AnnualisedReturn / MaxDrawdownFraction
  VaR_95  = −(μ − 1.645×σ) × Balance      (parametric, normal)
  CVaR_95 = −(μ − σ×φ(Φ⁻¹(0.05))/0.05) × Balance
            where φ ≈ 0.10313 (PDF of standard normal at z=-1.645)

The C++ build is optional. The app runs without it using NumPy.

WINDOWS — Option 1: batch script
  cd ApexForexBroker

WINDOWS — Option 2: MSVC manually
  cd cpp
  cl /O2 /LD /EHsc /std:c++17 /Iinclude
     /Fe:..\python\cpp\math_engine.dll src\math_engine.cpp

WINDOWS — Option 3: MinGW
  cd cpp
  g++ -std=c++17 -O3 -shared -fPIC -Iinclude
      -o ..\python\cpp\math_engine.dll src\math_engine.cpp -lm

LINUX
  cd ApexForexBroker
  bash scripts/build_cpp.sh
  # or manually:
  g++ -std=c++17 -O3 -shared -fPIC -Icpp/include
      -o python/cpp/math_engine.so cpp/src/math_engine.cpp -lm

macOS
  g++ -std=c++17 -O3 -dynamiclib -Icpp/include
      -o python/cpp/math_engine.dylib cpp/src/math_engine.cpp -lm

CMAKE (all platforms)

  cmake -B build -DCMAKE_BUILD_TYPE=Release
