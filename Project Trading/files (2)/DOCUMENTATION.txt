SECTION 1  —  OVERVIEW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Apex Forex Broker is a fully self-hosted desktop forex trading platform.
You are the broker. All order execution, position management, margin
calculation, and trade journaling happen locally on your machine.
No third-party broker, no cloud dependency, no subscription.

Key capabilities:

  ► 12 forex pairs + Gold + Silver  streamed live via WebSocket
  ► Full manual trading: market orders, limit orders, stop orders
  ► Modify stop-loss / take-profit on open positions
  ► Trailing stop system (ATR-based)
  ► Automatic signal system: 22 indicators fused into BUY/SELL signals
  ► Machine-learning filter (Random Forest / Gradient Boosting)
  ► Risk management: Kelly criterion, VaR, CVaR, Sharpe, Sortino, Calmar
  ► Margin monitoring with margin call and stop-out protection
  ► Full trade history with CSV export
  ► Performance analytics with equity curve, win-rate, profit factor
  ► 30+ technical indicators: EMA, MACD, RSI, Ichimoku, SuperTrend, BB...
  ► Light-mode professional GUI

SECTION 3  —  INSTALLATION: RUNNING FROM PYTHON SOURCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Step 1 — Install Python
  Download Python 3.11 from https://www.python.org/downloads/
  During installation, check "Add Python to PATH"

Step 2 — Extract the project
  Unzip or copy the ApexForexBroker folder to any location, e.g.:
    C:\ApexForexBroker\

Step 3 — Open a terminal in the project folder
  Windows: Right-click in the folder → "Open in Terminal"
           or press Win+R, type cmd, press Enter,
           then: cd C:\ApexForexBroker

Step 4 — Install dependencies
  pip install -r requirements.txt

  If pip is not found:
    python -m pip install -r requirements.txt

  On some systems with multiple Python versions:
    py -3.11 -m pip install -r requirements.txt

Step 5 — Run the application
  python main.py

  With debug logging:
    python main.py --debug

  Headless mode (no GUI, signals only to log):
    python main.py --headless

  Reset database (clear all trades):
    python main.py --reset-db

The application will start in DEMO mode by default.
Demo mode uses a built-in price simulator (no API key needed).
Prices update every second and the candlestick chart refreshes every 2 seconds.

SECTION 4  —  INSTALLATION: BUILDING THE WINDOWS EXE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

To create a standalone .exe that runs without Python installed:

Method A — Double-click build script (easiest)
  1. Make sure Python 3.10+ is installed and on PATH
  2. Double-click build_exe.bat in the project folder
  3. Wait 2–5 minutes while PyInstaller packages everything
  4. Find your EXE at: dist\ApexForexBroker.exe

Method B — Manual build
  Open a terminal in the project folder, then run:

    pip install pyinstaller
    pyinstaller --onefile --windowed --name "ApexForexBroker"       ^
        --hidden-import sklearn.ensemble                              ^
        --hidden-import sklearn.calibration                          ^
        --hidden-import matplotlib.backends.backend_tkagg            ^
        --hidden-import scipy.stats                                  ^
        --collect-all sklearn                                        ^
        main.py

  Output: dist\ApexForexBroker.exe  (typically 60–120 MB)

Distributing the EXE:
  Copy dist\ApexForexBroker.exe to any Windows 10/11 machine.
  The exe is self-contained — no Python, no packages needed on target machine.
  On first run, it creates config.json and db\broker.db in the same folder.

SECTION 5  —  RUNNING WITH LIVE MARKET DATA
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Apex Forex Broker supports four price feed modes. Choose one.

──────────────────────────────────────────────────────────────────────────────
MODE 1: DEMO (Default — No API key required)
──────────────────────────────────────────────────────────────────────────────
  The built-in simulator generates realistic synthetic prices using:
    • Geometric Brownian Motion (GBM) — realistic random walk
    • Ornstein-Uhlenbeck mean reversion — prices drift back to fair value
    • Trend injection — random trending periods of 50–300 ticks
    • News spike simulation — rare random spikes in volatility
  Tick rate: 1 tick per second per pair (12 pairs = 12 ticks/sec total)
  Config: "provider": "demo"  (this is the default)

  To use demo mode:
    python main.py
    (or just double-click the EXE)

──────────────────────────────────────────────────────────────────────────────
MODE 2: TWELVE DATA (WebSocket — Free tier available)
──────────────────────────────────────────────────────────────────────────────
  Twelve Data provides real-time forex prices via WebSocket.
  Free plan: 8 symbols, 1 WebSocket connection.
  Paid plans: all symbols.

  Sign up: https://twelvedata.com/
  After signing up, copy your API key.

  Configure config.json:
    "data_source": {
      "provider": "twelvedata",
      "api_key":  "YOUR_API_KEY_HERE"
    }

  Or set environment variable:
    set APEX_API_KEY=YOUR_API_KEY_HERE
    set APEX_PROVIDER=twelvedata
    python main.py

  Connection: wss://ws.twelvedata.com/v1/quotes/price?apikey=KEY
  Reconnect:  Automatic with exponential backoff (5s, 10s, 20s…)

──────────────────────────────────────────────────────────────────────────────
MODE 3: POLYGON.IO (WebSocket — Free tier available)
──────────────────────────────────────────────────────────────────────────────
  Polygon.io offers real-time forex data including all major pairs.
  Free plan: End-of-day data only. Starter plan: Real-time.

  Sign up: https://polygon.io/
  After signing up, copy your API key.

  Configure config.json:
    "data_source": {
      "provider": "polygon",
      "api_key":  "YOUR_API_KEY_HERE"
    }

  Connection: wss://socket.polygon.io/forex
  Authentication: Handled automatically on connection.

──────────────────────────────────────────────────────────────────────────────
MODE 4: OANDA (REST Streaming — Requires funded account)
──────────────────────────────────────────────────────────────────────────────
  OANDA is a major retail forex broker with an open REST API.
  You need an OANDA account (demo or live).

  Steps:
  1. Create account at https://www.oanda.com/
  2. Go to Manage API access in your account settings
  3. Generate a personal access token
  4. Find your Account ID in the account overview

  Configure config.json:
    "data_source": {
      "provider":      "oanda",
      "api_key":       "YOUR_OANDA_TOKEN",
      "websocket_url": "https://stream-fxtrade.oanda.com"
    }

  For OANDA practice (demo) accounts:
    "websocket_url": "https://stream-fxpractice.oanda.com"

──────────────────────────────────────────────────────────────────────────────
KEEPING PRICES LIVE STREAMED WHILE RUNNING LOCALLY
──────────────────────────────────────────────────────────────────────────────
  As long as the application is running (Python script or EXE), the price
  feed runs in a background thread continuously receiving WebSocket data.
  No web server, no cloud, no VPS required. The market data flows directly
  from your chosen provider to your desktop, in real time.

  The chart refreshes every 2 seconds by default.
  The watchlist updates every 2 seconds.
  The account panel updates every 2 seconds.

  To change the refresh rate, edit config.json:
    "ui": { "refresh_ms": 1000 }   ← 1 second refresh (higher CPU usage)
    "ui": { "refresh_ms": 5000 }   ← 5 second refresh (lower CPU usage)

SECTION 9  —  MANUAL TRADING — MARKET ORDERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Go to the "📈 Trading" tab. The left column is the Market Order panel.

  Fields:
    Instrument   — Select the forex pair from the dropdown
    Bid / Ask    — Live current bid and ask prices (updates every second)
    Lot Size     — Size of the trade in lots. Use the spinner (up/down arrows)
                   or type directly. Min: 0.01. Step: 0.01
    Stop Loss    — Enter the stop-loss price level. Enter 0 to have no SL.
    Take Profit  — Enter the take-profit price level. Enter 0 for no TP.
    Comment      — Optional text label for this trade (up to ~50 chars)
    Margin req.  — Calculated margin requirement for this lot size (shown live)

  Buttons:
    ▲ BUY   — Opens a long position at current ASK price + slippage
    ▼ SELL  — Opens a short position at current BID price - slippage

  What happens when you click BUY or SELL:
    1. Pre-trade checks: lot size, max positions, margin level, daily loss
    2. Slippage applied: 1 pip by default (configurable)
    3. Margin requirement calculated and checked against free margin
    4. Commission deducted: $7.00 per standard lot (configurable)
    5. Position opened and stored in database
    6. Entry appears in the Positions tab immediately
    7. Confirmation message appears in the Log tab

  Lot size reference:
    0.01 lots (1 micro lot)  = $0.10 per pip  on major pairs
    0.10 lots (1 mini lot)   = $1.00 per pip  on major pairs
    1.00 lots (1 standard)   = $10.00 per pip on major pairs

SECTION 10  —  MANUAL TRADING — PENDING ORDERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  The middle column of the Trading tab handles pending orders.

  Order types:
    BUY_LIMIT    — Buy when price falls to your specified price
                   (must be below current ask)
    SELL_LIMIT   — Sell when price rises to your specified price
                   (must be above current bid)
    BUY_STOP     — Buy when price rises to your specified price
                   (must be above current ask)
    SELL_STOP    — Sell when price falls to your specified price
                   (must be below current bid)

  Fields:
    Instrument   — Select the pair
    Order Type   — Select from the 4 types above
    Lot Size     — Trade size in lots
    Price        — Trigger price for the order
    Stop Loss    — SL for when the order executes (0 = no SL)
    Take Profit  — TP for when the order executes (0 = no TP)
    Expire (sec) — Seconds until the order expires (0 = GTC = never)

SECTION 13  —  SIGNAL SYSTEM — HOW IT WORKS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  The signal engine runs continuously in the background, analysing price
  bars for every pair on the primary timeframe (default: 15min).

  Pipeline:
    1. Price ticks → BarAggregator → OHLCV bars (per timeframe)
    2. On each completed bar → SignalEngine.on_bar()
    3. 22 indicator strategies each cast a VOTE (BUY, SELL, or ABSTAIN)
    4. Each vote has a WEIGHT (see Section 14)
    5. Bull weight and bear weight are summed
    6. If bull_weight > bear_weight AND bull_votes ≥ min_confluence (3):
         direction = BUY, confidence = bull_weight / total_weight
    7. If bear_weight > bull_weight AND bear_votes ≥ min_confluence:
         direction = SELL, confidence = bear_weight / total_weight
    8. If confidence < 0.52 → signal discarded (too weak)
    9. Cooldown check: minimum 300 seconds between signals per pair
   10. Spread filter: signal blocked if spread > 3 pips (configurable)
   11. Stop Loss = entry ± 2.0 × ATR(14)
       Take Profit 1 = entry ± 4.0 × ATR(14)  (2:1 risk:reward)
       Take Profit 2 = entry ± 6.0 × ATR(14)
       Take Profit 3 = entry ± 8.0 × ATR(14)
   12. Position size calculated by Kelly-adjusted fixed-fraction sizing
   13. Signal saved to database and displayed in the Signals panel
   14. If auto-trade is ON: trade is opened automatically

  Signal strength levels:
    WEAK         — confidence 52–60%   (1 dot)
    MODERATE     — confidence 60–70%   (2 dots)
    STRONG       — confidence 70–80%   (3 dots)
    VERY STRONG  — confidence ≥ 80%    (4 dots)

SECTION 16  —  RISK MANAGEMENT SYSTEM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The risk system runs several protective mechanisms simultaneously:

POSITION SIZING (Kelly-Adjusted Fixed Fraction)
  ──────────────────────────────────────────────
  The system sizes every trade using the formula:

    risk_usd  = Balance × risk_per_trade_pct / 100
    sl_pips   = |entry_price - stop_loss| / pip_size
    raw_lots  = risk_usd / (sl_pips × pip_value_per_lot)
    final_lots = raw_lots × kelly_fraction

  where kelly_fraction is further adjusted by the historical Kelly criterion:

    Kelly f* = (b × p − q) / b

    p = historical win rate
    q = 1 − p
    b = average_win / average_loss

  This ensures position sizes automatically shrink after a losing streak
  and grow (conservatively) during winning periods.

STOP LOSS / TAKE PROFIT
  ─────────────────────
  Automatic SL and TP levels are calculated using ATR (Average True Range):
    SL distance = ATR(14) × sl_atr_multiplier  (default: 2.0)
    TP distance = SL distance × tp_risk_reward  (default: 2.0)
  This means TP is always at least 2× the distance of SL by default,
  giving a minimum 2:1 risk-to-reward ratio on every signal.

TRAILING STOP
  ────────────
  When trailing stop is enabled (default: on), the stop loss automatically
  moves in the direction of the trade as profit increases.
  The trail preserves the original SL distance from the current price.
  This means once the price moves 1× your SL distance in your favour,
  the trade is essentially risk-free (SL is at breakeven).

DAILY LOSS BREAKER
  ─────────────────
  If total closed losses for the day exceed max_daily_loss_pct of balance,
  all new trade entries are blocked (including auto-trades).
  This protects against a cascade of losses in a single session.
  The breaker resets at midnight UTC.

MARGIN CALL WARNING
  ──────────────────
  Default trigger: Margin Level falls below 50%
  Warning appears in the alert bar and in the Log tab.
  New trades are blocked when margin level < margin_call_pct.

STOP-OUT (FORCED CLOSE)
  ──────────────────────
  Default trigger: Margin Level falls below 20%
  ALL open positions are automatically closed to prevent the account
  from going negative. This is your last line of protection.

SECTION 21  —  FINANCIAL MATHEMATICS REFERENCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

All calculations are performed locally. No external calculation service.

ACCOUNT CALCULATIONS
  Margin Required  = (Lots × Contract_size × Price) / Leverage
                     Contract size = 100,000 units for forex
                     XAU = 100 oz per lot, XAG = 5,000 oz per lot
  Equity           = Balance + Floating_PnL
  Free Margin      = Equity − Margin_Used
  Margin Level     = (Equity / Margin_Used) × 100 %
  PnL (BUY)        = (Close − Open) / Pip_size × Pip_value × Lots
  PnL (SELL)       = (Open − Close) / Pip_size × Pip_value × Lots
  Pip value (USD)  = varies by pair (EUR/USD: $10/pip/lot; USD/JPY: ~$9.09)
  Daily swap        = Lots × Swap_rate_pips/night × Pip_value
  Commission        = Lots × Commission_per_lot  (default $7/lot)

POSITION SIZING
  Risk USD          = Balance × Risk_pct / 100
  SL pips           = |entry − stop_loss| / pip_size
  Raw lots          = Risk_USD / (SL_pips × pip_value_per_lot)
  Kelly f*          = (b × p − q) / b
    where  b = avg_win / avg_loss, p = win_rate, q = 1 − win_rate
  Final lots        = Raw_lots × (Kelly_f* × kelly_fraction)
  Clamped to        [min_lot, max_lot] with lot_step rounding

PERFORMANCE METRICS
  Sharpe Ratio      = (μ_r − r_f) / σ_r × √252
    μ_r = mean return per trade, r_f = risk-free rate (0), σ_r = std dev
  Sortino Ratio     = (μ_r − r_f) / σ_down × √252
    σ_down = downside deviation (negative returns only)
  Calmar Ratio      = Annualised_return / Max_drawdown_fraction
  Profit Factor     = Gross_profit / Gross_loss
  Expectancy        = Win_rate × Avg_win − Loss_rate × Avg_loss
  Max Drawdown      = Maximum peak-to-trough decline in cumulative P&L

VALUE AT RISK (Parametric, 95% confidence, normal distribution)
  VaR_95            = −(μ − 1.645 × σ) × Balance
    where μ, σ are mean and std dev of returns per trade
  CVaR_95 (ES)      = −(μ − σ × φ(Φ⁻¹(0.05)) / (1 − 0.05)) × Balance
    = Expected Shortfall: average loss in the worst 5% of cases
    φ = PDF of standard normal ≈ 0.10313

INDICATOR MATHEMATICS
  EMA(n)          = (price − prev_EMA) × k + prev_EMA   k = 2/(n+1)
  SMA(n)          = mean of last n closes
  WMA(n)          = weighted mean, weights = 1, 2, …, n
  HMA(n)          = WMA(2×WMA(n/2) − WMA(n), √n)
  KAMA            = Adaptive MA using Efficiency Ratio
  Kalman          = Optimal linear state estimator (noise reduction)
  RSI(n)          = 100 − 100/(1 + avg_gain/avg_loss)  over n periods
  MACD            = EMA(fast) − EMA(slow),  Signal = EMA(MACD, sig)
  BB              = SMA(n) ± std × σ(n)
  ATR             = EMA(True_Range, n)
  ADX             = Smoothed(DX), DX = |DI+ − DI−| / (DI+ + DI−)
  Stochastic %K   = 100 × (Close − Low_n) / (High_n − Low_n)
  CCI             = (TP − SMA(TP)) / (0.015 × MAD)
  Williams %R     = −100 × (High_n − Close) / (High_n − Low_n)
  SuperTrend      = (High+Low)/2 ± ATR × multiplier  with flip logic
  Ichimoku        = Tenkan=(H+L)/9, Kijun=(H+L)/26, Senkou=(H+L)/52
  VWAP            = Σ(TP×V) / Σ(V)  (cumulative from bar open)
  OBV             = Σ (volume if up, −volume if down)
  Squeeze         = Bollinger inside Keltner detection
  Hurst Exponent  = R/S analysis  (> 0.5 = trending, < 0.5 = reverting)
  Z-Score         = (price − mean_n) / std_n

PROBLEM: "ModuleNotFoundError: No module named 'numpy'"
SOLUTION: Run from the correct folder and install packages.
  Open terminal IN the project folder (where main.py lives), then:
    pip install -r requirements.txt
  Make sure you are using the same Python that pip installed to:
    python --version
    pip --version

PROBLEM: "ModuleNotFoundError: No module named 'core'"
SOLUTION: You are not running from the project root directory.
  The terminal must be in the folder that contains main.py.
    cd C:\ApexForexBroker      ← change to YOUR actual folder path
    python main.py

PROBLEM: GUI window is blank / chart doesn't appear
SOLUTION: matplotlib may not have the TkAgg backend.
  Try: pip install --upgrade matplotlib Pillow
  If on Linux: sudo apt-get install python3-tk

PROBLEM: "No price available for EUR/USD"
SOLUTION: Price feed hasn't started yet. Wait 3–5 seconds for the
  first ticks to arrive. In demo mode this happens automatically.
  In live mode, check your API key in config.json.

PROBLEM: WebSocket keeps disconnecting
SOLUTION: Normal behaviour on unstable connections — auto-reconnect
  handles it. Check your internet connection. In config.json you can
  increase "reconnect_delay" to 10 seconds to avoid hammering the server.

PROBLEM: Signals never appear
SOLUTION: Need at least 50 completed bars before analysis begins.
  On 15min chart in demo mode: wait at least 50 minutes.
  For faster testing, change "primary_tf" to "1min" in config.json.
  Then signals may appear within 50 minutes of starting.

PROBLEM: ML filter never votes
SOLUTION: The ML model requires min_samples (default 200) completed
  bars before it trains. On 15min timeframe this takes ~50 hours.
  Reduce "primary_tf" to "1min" and "min_samples" to 100 for faster ML.

PROBLEM: The EXE shows a Windows security warning
SOLUTION: This is normal for unsigned executables.
  Click "More info" → "Run anyway" on the SmartScreen dialog.
  Or right-click the EXE → Properties → Unblock.

PROBLEM: EXE crashes immediately / black window appears and closes
SOLUTION: A startup error occurred. Run from Python source instead
  to see the error message:
    python main.py --debug
  Check the logs/ folder for broker.log with error details.

PROBLEM: Very high CPU usage
SOLUTION: Reduce refresh rate. In config.json:
    "ui": { "refresh_ms": 5000 }
  Also reduce the number of pairs:
    "pairs": ["EUR/USD", "GBP/USD", "USD/JPY"]

SECTION 23  —  FAQ
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: Is this real trading with real money?
A: No. Apex Forex Broker is a self-hosted simulation/paper trading system.
   All orders are executed internally against the price feed. No real broker
   is involved, no real money moves, no real trades are placed.
   It is a decision support and training tool.

Q: Can I connect it to a real broker?
A: The OANDA price feed provides real market prices, but the order execution
   is still local. To place real orders you would need to integrate the
   OANDA v20 REST API order endpoints into the trading engine.

Q: Where is my data stored?
A: Everything is local. The SQLite database is at db/broker.db.
   Trade history CSV is at reports/trades.csv.
   Log files are at logs/broker.log.
   No data leaves your machine.

Q: How do I reset my account balance?
A: Option 1: Run with --reset-db flag. This wipes ALL data.
   Option 2: Edit the database directly with SQLite Browser:
     UPDATE accounts SET balance=10000, equity=10000, free_margin=10000;
   Option 3: Delete db/broker.db and restart.

Q: How do I change my starting balance?
A: In config.json, set:
     "account": { "initial_balance": 50000 }
   This only takes effect the FIRST time you run (when the DB is created).
   To apply to an existing database, use --reset-db.

Q: What happens to my positions if I close the app?
A: Open positions are saved in the database. When you restart, they are
   still there. However, any P&L changes while the app was closed are not
   tracked. The prices will update to current levels on restart.

Q: The signals look too frequent / not frequent enough. How do I tune this?
A: In config.json:
   • Increase "min_confluence" to 4 or 5 for fewer, higher-quality signals
   • Increase "signal_cooldown" to 600 or 900 for signals spaced further apart
   • Increase "min_confidence" to 0.65 for only strong signals
   • Change "primary_tf" to a higher timeframe (e.g. "1h" or "4h")

Q: Why does the last candlestick keep changing shape?
A: This is normal and correct. The rightmost candle is the "live" candle
   for the current period. Its close price updates with every tick. When
   the period ends, the candle is finalised and a new one begins.

Q: How do I add more currency pairs?
A: In config.json, add pairs to the "pairs" list:
     "pairs": ["EUR/USD", "GBP/USD", ..., "USD/SGD"]
   Make sure your data provider supports those pairs.
   The demo simulator supports only the 12 default pairs.

Q: Can I run multiple instances?
A: Yes, but they must use different database files.
   Run with: python main.py --config my_second_account.json
   And in that config, change the db path settings.

Q: How do I increase leverage?
A: In config.json: "account": { "leverage": 500 }
   Higher leverage means higher profit potential but also higher risk.
   The margin requirement and risk calculations adjust automatically.
